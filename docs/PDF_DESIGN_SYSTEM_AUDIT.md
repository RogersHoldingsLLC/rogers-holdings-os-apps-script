# Rogers Holdings OS PDF Design System Audit

Date: 2026-06-27

Purpose: establish one customer-facing PDF design system before future visual improvements. This audit preserves current business logic, calculations, workflow behavior, generated data, Drive filenames, and Gmail attachment behavior.

## PDF Inventory

| PDF | Generator | Filename | Audience | Workflow |
| --- | --- | --- | --- | --- |
| Website Audit Report | `buildAuditReportPdfBlob_()` | `Audit Report.pdf` | Customer-facing | Generated by Audit Package and Full Prospect Package workflows |
| Proposal | `buildProposalPdfBlob_()` | `Proposal.pdf` | Customer-facing | Generated by Audit Package and Full Prospect Package workflows |

The two customer-facing PDFs are stored by `storeAuditPackageFiles_()` and attached by `sendAuditPackage()` using the existing filenames. The Discovery Call Brief uses the same branded wrapper but is positioned as an internal document.

Current shared PDF rendering components:

- `buildBrandedPdfHtml_()` - full HTML document shell, shared CSS, fixed header, fixed footer, watermark.
- `brandedPdfCoverHtml_()` - split cover layout with side panel, logo, customer name, date, and document title.
- `brandedPdfSectionHtml_()` - standard body section wrapper and section heading.
- `brandedPdfDividerPageHtml_()` - full-page black/gold divider page.
- `executiveSummaryCardsHtml_()` - KPI/summary card grid.
- `recommendationCardsHtml_()` - repeated recommendation/finding cards.
- `brandedPdfDefinitionListHtml_()` - two-column label/value blocks.
- `brandedPdfListHtml_()` - standard bullet list.
- `deliverableCardsHtml_()` - proposal deliverable cards.
- `buildWebsiteScreenshotHtml_()` - screenshot section with desktop and mobile framing.
- `htmlToPdfBlob_()` - final Apps Script HTML-to-PDF conversion.
- `getRogersBrandPdfAssets_()` - dynamic Drive-based brand asset loading.
- `getPdfDesignSystem_()` - shared design tokens and component registry for the current PDF system.

## Inconsistency Audit

### Typography

- Body text is consistently Arial at 12px inside `buildBrandedPdfHtml_()`.
- Labels use uppercase small text, but label sizing is repeated in several CSS classes.
- Cover titles, section titles, card titles, and proof headings are visually aligned but not yet fully tokenized.

Recommendation: keep Arial for Apps Script PDF reliability; future polish should move all font sizes and label styles through `getPdfDesignSystem_()`.

### Margins

- Body pages use `.section { padding: 82px 48px 18px; }`.
- Header/footer use fixed positions with 44px horizontal spacing.
- Cover and divider pages use separate full-page layouts.

Recommendation: preserve the current 48px body margin and 44px footer/header margin as the standard PDF margin system.

### Spacing

- Card gaps are mostly 14px.
- Most card padding is 16px.
- Some complex sections use one-off spacing for screenshots, proof cards, signature rows, and cover elements.

Recommendation: standardize future card spacing at 14px gap / 16px padding; reserve custom spacing only for covers, dividers, screenshots, and signature pages.

### Header Layouts

- The shared fixed header is consistent across PDFs and uses the primary Rogers Holdings logo when available.
- Divider pages intentionally bypass the fixed header visually through full-page dark treatment.
- Cover pages do not rely on the fixed header, which is correct.

Recommendation: keep the fixed header for interior pages only. Do not add competing logos inside ordinary section bodies unless required by a special page type.

### Footer Layouts

- Footer is shared inside `buildBrandedPdfHtml_()`.
- Footer includes company, Brian Keith Rogers, email, phone, and document title.
- No explicit page numbering currently exists.

Recommendation: keep the current footer content; page numbering remains a future enhancement because Apps Script HTML-to-PDF page counters can be inconsistent.

### Logo Placement

- Cover: primary logo appears in the dark side panel.
- Interior: primary logo appears in the fixed header.
- Watermark: low-opacity logo appears fixed near the bottom-right.
- Divider: centered logo plus subtle watermark.

Recommendation: keep this hierarchy. Avoid placing the same logo repeatedly inside body cards.

### Tables

- PDFs currently avoid heavy tables and use cards, definition lists, grids, timelines, and checklists.
- This matches the premium consulting deliverable direction.

Recommendation: future tables should use minimal borders, gold dividers, and small uppercase headers.

### Recommendation Sections

- Audit Report uses findings cards, proof cards, quick wins, roadmap cards, checklist cards, and service package cards.
- Proposal uses solution, deliverables, timeline, investment, next steps, and acceptance sections.
- Discovery Call Brief uses the same recommendation card helper, even though it is internal.

Recommendation: keep customer-facing recommendation sections concise and card-based; avoid paragraph-heavy recommendation blocks.

### Colors

Current standards:

- Black: `#111111`
- Charcoal: `#05070a`
- Gold: `#d6a84f`
- Dark gold: `#b88728`
- Soft gold border: `#d8c7a4`
- Light gold border: `#e6dac2`
- Body background: `#ffffff`
- Card background: `#fbfaf7`
- Muted text: `#6f6a60`
- Success: `#2f6f45`
- Danger: `#8a2f2f`

Recommendation: these are now captured in `getPdfDesignSystem_()` and should be reused for future PDF improvements.

### Page Numbering

- No reliable page numbering is implemented.
- Current footer identifies the document but not the page number.

Recommendation: defer page numbering unless the PDF renderer is upgraded or page counters are proven reliable in Apps Script.

## Reusable PDF Design System

### Document Types

- Audit Report: customer-facing diagnostic and recommendation document.
- Proposal: customer-facing commercial next-step document.
- Discovery Call Brief: internal preparation document using the same brand shell.

### Page Types

- Cover page: dark split-panel branded opening page.
- Executive summary page: metric cards plus short customer-facing summary.
- Screenshot/evidence page: browser/device frame with concise observed notes.
- Divider page: full black/charcoal page with centered logo, gold rules, and white title.
- Findings page: consulting cards with observation, evidence, impact, and recommended action.
- Roadmap page: concise phased cards.
- Proposal solution page: recommendation, deliverables, timeline, investment.
- Acceptance page: brief approval summary and signature lines.

### Component Standards

- Use `buildBrandedPdfHtml_()` for every generated PDF.
- Use `brandedPdfCoverHtml_()` for every opening page.
- Use `brandedPdfSectionHtml_()` for ordinary sections.
- Use `brandedPdfDividerPageHtml_()` only for major transitions.
- Use card helpers instead of freeform tables for customer-facing content.
- Use `getRogersBrandPdfAssets_()` for all brand images.
- Use `getPdfDesignSystem_()` for colors, typography, spacing, and component naming.

## AI-Ready Evidence Contract

Future AI modules should populate a normalized evidence object instead of changing PDF rendering logic.

Supported provider interfaces:

- `captureWebsite(prospect, reportFile)`
- `captureMobile(prospect, reportFile)`
- `captureGoogleBusiness(prospect, reportFile)`
- `capturePageSpeed(prospect, reportFile)`
- `captureSearchResults(prospect, reportFile)`
- `annotateEvidence(evidenceObject, finding)`
- `generateBusinessInterpretation(prospect, reportFile)`

Preferred evidence object shape:

```js
{
  website: {
    screenshotDataUri: '',
    screenshotUrl: '',
    homepageText: '',
    detectedElements: {},
    missingElements: [],
    annotations: []
  },
  mobile: {
    screenshotDataUri: '',
    screenshotUrl: '',
    notes: ''
  },
  googleBusiness: {
    profileUrl: '',
    evidenceText: '',
    status: ''
  },
  pageSpeed: {
    score: '',
    loadTime: '',
    evidenceText: ''
  },
  searchResults: {
    query: '',
    rankSummary: '',
    evidenceText: ''
  },
  interpretation: {
    summary: ''
  }
}
```

The PDF renderer should only render available evidence. It should not own screenshot capture, search capture, PageSpeed capture, or AI interpretation generation.
