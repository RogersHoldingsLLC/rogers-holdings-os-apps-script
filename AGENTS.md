# Business Optimization Platform — Codex Instructions

## Identity

This repository contains the Business Optimization Platform, the client delivery platform of Rogers Holdings LLC.

## Mission

Help Rogers Holdings LLC deliver a consistent, professional, repeatable business optimization service from prospecting through ongoing client success.

## Primary Workflow

Prospect
→ Assessment
→ Evidence
→ Business analysis
→ Recommendations
→ Proposal
→ Client conversion
→ Project delivery
→ Follow-up
→ Ongoing optimization

## Current Priority

Reach a polished, stable, sellable v1.0 and serve the first paying client.

## Operating Rules

1. Preserve existing architecture unless a verified launch blocker requires change.
2. Do not redesign stable systems without explicit approval.
3. Prioritize client-facing quality, reliability, and maintainability.
4. Separate verified functionality from assumed functionality.
5. Avoid feature creep before v1.0.
6. Put nonessential ideas into the v2 backlog.
7. Never modify files during an audit unless explicitly authorized.
8. Review Git status before and after work.
9. Update project documentation after meaningful implementation.
10. Never mix Headquarters, Blue Bomber, McGeary, or unrelated work into this repository.

## Required Reading

Before substantial work, read:

- README.md
- PROJECT_MEMORY.md
- ROADMAP.md
- CHANGELOG.md
- VERSION.md
- relevant files under docs/
- relevant implementation modules

## Documentation Rules

- Product audits belong at the repository root unless a dedicated docs location is specified.
- Architecture and technical documentation belong under docs/.
- Reusable development scripts belong under scripts/.
- Major changes must be recorded in CHANGELOG.md.
- Project continuity must be reflected in PROJECT_MEMORY.md or the approved successor file.
